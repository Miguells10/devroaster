# Spec Format Guide

Always create a spec in this folder before implementing a new feature.

## 1. Context & Objective
What are we building and why?

## 2. Approach & Research
Comparison of solutions and why we chose the current path.

## 3. Dependencies
New libraries or tools required.

## 4. Functional Spec
- Behavior and interactions.
- UX/UI details.
- MVP scope.

## 5. Technical Spec
- File structure (`src/components/...`).
- Database schema changes.
- Key logic/snippets.

## 6. Open Questions
Critical decisions pending user approval.

## 7. References
Documentation, GitHub repos, or design inspirations.
